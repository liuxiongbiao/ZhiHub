# Feature Specification: 账号体系 + 多租户闭环

**Feature Branch**: `001-account-tenant`

**Created**: 2026-08-04

**Status**: Draft

**Input**: User description: "Day 2 账号体系 + 多租户闭环：手机号注册 → 自动创建租户(trial套餐) → 登录拿JWT → 进后台首页全链路。核心能力：JWT鉴权中间件、租户上下文中间件、依赖注入(get_current_user/require_role/require_tenant)、注册事务编排、登录校验(密码强度、失败锁定)、登出token黑名单。验收：注册手机号自动建trial租户→登录成功→进后台首页；退出后旧token立即失效；坐席角色token无法调用管理员接口。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 企业管理员注册并开通租户 (Priority: P1)

一位企业客服主管首次到达平台，用手机号 + 密码注册。注册成功的瞬间，系统为其企业创建一个全新的租户（默认试用版套餐），并把该用户设为这个租户的管理员。此后这个用户的一切数据都归属于这个租户。

**Why this priority**：没有"注册即建租户 + 绑定管理员"这一步，后续所有功能都没有归属主体，多租户隔离无从谈起。这是整个系统的入口，也是本 feature 的最小可用切片。

**Independent Test**：调用注册接口提交一个全新手机号 + 合规密码 + 企业名称，验证返回成功，且数据库中新增了一条用户记录、一条试用版租户记录、一条"该用户是该租户管理员"的成员关联记录。

**Acceptance Scenarios**：

1. **Given** 一个从未注册过的手机号，**When** 提交手机号 + 合规密码 + 企业名称完成注册，**Then** 系统创建用户、创建试用版（trial）租户、建立管理员成员关联，三者在同一事务内成功或全部回滚。
2. **Given** 一个已被注册的手机号，**When** 再次用它注册，**Then** 系统拒绝并提示"该手机号已注册，请登录或找回密码"，不产生任何新记录。
3. **Given** 一个不满足强度要求的密码（如纯数字 `12345678`、少于 8 位、或常见弱密码 `password`），**When** 提交注册，**Then** 系统拒绝并说明密码强度要求，不创建任何记录。
4. **Given** 注册过程中租户创建或成员关联写入失败，**When** 事务提交，**Then** 已写入的用户记录一并回滚，不留下"有用户但无租户"的孤儿数据。

---

### User Story 2 - 登录获取访问凭证并进入后台 (Priority: P1)

已注册的管理员用手机号 + 密码登录。凭证正确即获得一个访问令牌，携带该令牌可以进入后台首页并被系统识别为"某租户下的某管理员"。

**Why this priority**：注册后必须能登录进入系统，否则注册无意义。登录同时确立了"当前请求是谁、属于哪个租户、什么角色"这一贯穿全系统的上下文。

**Independent Test**：用 Story 1 注册的账号提交正确的手机号 + 密码，验证返回一个有效访问令牌；携带该令牌访问后台首页接口返回成功，且系统能识别出正确的用户身份、租户归属与角色。

**Acceptance Scenarios**：

1. **Given** 一个已注册且密码正确的账号，**When** 提交登录，**Then** 返回访问令牌，令牌可用于后续请求并被解析出正确的用户、租户、角色。
2. **Given** 密码错误，**When** 提交登录，**Then** 拒绝登录，并累计该账号的连续失败次数。
3. **Given** 同一账号连续 5 次密码错误，**When** 第 5 次失败后，**Then** 账号锁定 15 分钟，锁定期内即使密码正确也拒绝登录，并提示剩余锁定时间。
4. **Given** 携带有效令牌，**When** 访问后台首页接口，**Then** 请求通过鉴权与租户上下文注入，返回该用户所属租户的首页数据。
5. **Given** 未携带令牌或令牌无效/过期，**When** 访问需鉴权接口，**Then** 系统拒绝并返回未认证错误。

---

### User Story 3 - 登出即时失效 (Priority: P2)

管理员点击登出后，其刚才持有的令牌必须立即作废，即使该令牌本身尚未到过期时间，也不能再用于任何请求。

**Why this priority**：无状态令牌"登出后仍在有效期内可用"是真实的安全缺口。这是本 feature 的关键安全验收点之一，但依赖 Story 1、2 已就绪。

**Independent Test**：登录拿到令牌 → 调用登出接口 → 再用同一个令牌访问需鉴权接口，验证被拒绝。

**Acceptance Scenarios**：

1. **Given** 一个有效的、未过期的令牌，**When** 用户调用登出，**Then** 该令牌被加入黑名单，其黑名单存续时间等于该令牌距原过期时间的剩余时长。
2. **Given** 一个已登出（在黑名单中）的令牌，**When** 用它访问任何需鉴权接口，**Then** 系统直接拒绝，即使令牌签名有效、未到过期时间。

---

### User Story 4 - 接口级角色权限隔离 (Priority: P2)

坐席角色的令牌只能访问会话处理、工单/订单相关接口，无法访问账单、套餐变更、成员邀请、知识库删除等管理员专属接口——这个限制在接口层强制执行，而不仅是前端隐藏菜单。

**Why this priority**：越权访问是安全红线（宪法原则 II）。本 feature 需先建好角色字段与接口级校验能力，并用负向测试证明拦截生效；完整的各业务接口拦截会随后续模块补齐。

**Independent Test**：用坐席角色令牌调用一个管理员专属接口，验证返回 403 拒绝；用管理员令牌调用同一接口，验证放行。

**Acceptance Scenarios**：

1. **Given** 一个坐席角色令牌，**When** 调用管理员专属接口，**Then** 系统返回 403 越权拒绝，不执行任何操作。
2. **Given** 一个管理员角色令牌，**When** 调用同一管理员专属接口，**Then** 系统放行。
3. **Given** 任意登录用户的令牌，**When** 请求经过租户上下文处理，**Then** 令牌中携带的租户身份被注入请求上下文，供下游查询做租户过滤；请求体或查询参数中客户端自报的租户身份一律被忽略。

---

### Edge Cases

- 携带一个"用户已被删除/停用但令牌仍有效"的令牌访问：应被视为无效身份拒绝。
- 令牌可被成功解析，但其指向的租户处于只读或已注销状态：读操作按租户状态放行/降级，写操作应被拒绝（本 feature 建立租户状态校验能力，具体各接口的读写区分随业务接口落地）。
- 短信验证码通道故障：本 feature 采用手机号 + 密码为唯一登录方式，验证码为 mock，不阻断核心登录链路。
- 并发登录失败计数：多个请求同时判定失败次数时，计数不应因竞态而少计导致锁定失效。
- 租户名称重复：允许重复，租户以其唯一标识区分，不以名称做唯一约束。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：系统 MUST 支持用手机号 + 密码 + 企业名称完成注册，且手机号在全系统内唯一。
- **FR-002**：注册成功 MUST 在同一事务内完成三件事：创建用户、创建默认试用版（trial）租户、建立"该用户为该租户管理员"的成员关联；任一失败则全部回滚。
- **FR-003**：系统 MUST 校验密码强度：至少 8 位、同时含字母和数字、拒绝纯数字/连续字符/常见弱密码；不合规则拒绝注册。
- **FR-004**：系统 MUST 对已注册手机号的重复注册返回明确提示且不产生新记录。
- **FR-005**：系统 MUST 支持手机号 + 密码登录，凭证正确时签发访问令牌。
- **FR-006**：访问令牌 MUST 携带足以识别用户身份、租户归属、角色的信息。
- **FR-007**：系统 MUST 累计单账号连续密码失败次数，连续 5 次失败后锁定该账号 15 分钟，锁定期内拒绝登录并提示剩余时间。
- **FR-008**：所有需鉴权接口 MUST 校验令牌有效性（签名、过期），无效则拒绝。
- **FR-009**：系统 MUST 在每个需鉴权请求中解析令牌并将当前用户身份注入请求上下文，供下游使用。
- **FR-010**：系统 MUST 从可信来源（令牌所载信息）提取租户身份并注入请求上下文；MUST NOT 采信客户端在请求体或查询参数中自报的租户身份。
- **FR-011**：用户登出时，系统 MUST 将当前令牌加入黑名单，黑名单存续时长等于令牌剩余有效期；后续携带该令牌的请求 MUST 被拒绝。
- **FR-012**：鉴权校验 MUST 在验证令牌签名/过期后再查询黑名单，命中黑名单即拒绝。
- **FR-013**：系统 MUST 提供接口级角色校验能力，能对指定接口限定可访问角色白名单，非白名单角色返回 403。
- **FR-014**：系统 MUST 提供租户状态校验能力（正常/只读/已注销），供下游据此放行或拒绝操作。
- **FR-015**：注册成功后新租户的套餐 MUST 默认为试用版，坐席名额上限为 1。
- **FR-016**：登录成功后，携带令牌 MUST 能访问后台首页并获得该租户范围内的数据。

### Key Entities

- **用户（User）**：平台的登录主体。关键属性：唯一手机号、密码哈希、所属身份信息。一个用户通过成员关联归属到租户。
- **租户（Tenant）**：一个企业的数据隔离边界与计费主体。关键属性：唯一标识、企业名称（可重复）、套餐类型（注册默认试用版）、租户状态（正常/只读/已注销）、坐席名额上限。贯穿系统所有数据的归属维度。
- **租户成员关联（TenantMember）**：用户与租户的多对多归属关系，承载角色（管理员 / 坐席）。注册时创建首条"管理员"关联。
- **访问令牌（AccessToken）**：登录签发的无状态凭证，内含用户身份、租户归属、角色，以及唯一标识与过期时间；可被登出加入黑名单而提前失效。
- **登录失败计数（LoginFailCounter）**：按账号维度记录连续密码失败次数，达阈值触发限时锁定。
- **令牌黑名单（TokenBlocklist）**：记录已登出但尚未自然过期的令牌，存续至其原过期时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：一个全新手机号可在一次注册操作内完成"用户 + 试用版租户 + 管理员关联"的创建，事务成功率与回滚正确性 100%（无孤儿数据）。
- **SC-002**：注册后的账号可用正确凭证登录并进入后台首页，端到端成功。
- **SC-003**：连续 5 次错误密码后账号被锁定 15 分钟，锁定期内正确密码同样被拒——可被负向测试稳定复现。
- **SC-004**：登出后原令牌 100% 无法再用于任何需鉴权接口。
- **SC-005**：坐席角色令牌访问管理员专属接口 100% 返回 403；管理员令牌访问同接口 100% 放行。
- **SC-006**：任何携带客户端自报租户身份的请求，其自报值 100% 不影响实际生效的租户过滤（以令牌所载租户为准）。

## Assumptions

- 本 feature 按 BUILD_PLAN Day 2 裁剪范围实现：登录方式仅"手机号 + 密码"，短信验证码为 mock、不阻断链路；邮箱注册、微信登录不在本切片范围内。
- 密码存储与令牌签发/解码所依赖的安全底座（bcrypt 哈希、含唯一标识与过期时间的令牌生成/解码）已由 Day 1 完成，本 feature 直接复用。
- 角色体系本切片建立"管理员 / 坐席"两类角色字段与接口级校验能力即可；各业务接口的完整角色拦截随后续模块逐步补齐。
- 试用版 30 天到期自动降级为只读、配置向导四步等完整生命周期逻辑不在本切片范围内，仅需保证租户默认试用版且状态字段可表达只读/注销。
- 失败计数、锁定、令牌黑名单依赖一个具备 TTL 能力的快速存储；本切片假定该基础设施可用。
