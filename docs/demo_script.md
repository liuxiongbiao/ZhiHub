# 智枢 ZhiHub 演示脚本

> 6个场景，按顺序演示，总计约15分钟。

## 准备工作

- [ ] `docker compose up -d` 全部容器 healthy
- [ ] `alembic upgrade head` 数据库迁移完成
- [ ] `python scripts/seed_data.py` 预置数据就绪
- [ ] 浏览器打开 `http://localhost` (Nginx → 前端)
- [ ] 已注册测试账号（手机号 13800138000, 密码 abc12345）

## 场景1: 知识问答（3分钟）⭐ 核心

**目标**: 展示 LangGraph 路由 → 混合检索 → 带引用回答的全链路。

1. 注册/登录 → 进入 Widget 对话界面
2. 输入: "如何升级套餐？"
3. 观察: 返回带 `来源：《产品使用手册》` 引用的回答
4. 追问: "那第二种方法呢？"
5. 观察: Router 做指代补全（"第二种"替换为完整查询），正确回答

**面试话术**: "这是 LangGraph 状态图的主链路——Router 先做意图识别和指代补全，然后 Knowledge Agent 调用混合检索引擎（Milvus向量+ES BM25→RRF融合→Rerank精排），最后由 LLM 基于检索片段生成带引用的回答，防止幻觉。"

---

## 场景2: 工单查询（2分钟）

**目标**: 展示 MCP 协议真实调用 + 槽位补全。

1. 输入: "我的工单进度怎么样了？"
2. 观察: Agent 反问 "请提供您的工单编号（格式：TK-XXXXXXXX）"
3. 输入: "TK-20240001"
4. 观察: 返回工单状态 "待处理" 及详情

**面试话术**: "工单 Agent 先检查槽位——发现缺少 ticket_id——反问用户补全。槽位齐全后通过 MCP 协议调用 ticket_server 的 get_ticket_status 工具。MCP 使用 JSON-RPC 2.0 标准协议，不是简单的函数调用。"

---

## 场景3: 退款转人工（3分钟）⭐ 核心

**目标**: 展示 Human-in-the-loop + 坐席认领互斥锁。

1. 输入: "我要退款！你们服务太差了！"
2. 观察: Router 判定 intent=sensitive_action + sentiment=angry → 强制转人工
3. 切到坐席工作台（另一个浏览器/隐身窗口，用 agent 角色登录）
4. 点击 "认领" 会话
5. 演示: 另一个坐席同时点认领 → 提示 "会话已被坐席 X 认领"

**面试话术**: "退款是敏感操作——Constitution III 规定无论 Agent 置信度多高都不能自动处理。转人工用 Redis SETNX 实现分布式锁，两个坐席同时认领同一会话只有一个成功。这是真实的生产级并发控制。"

---

## 场景4: 检索效果对比（2分钟）

**目标**: 展示纯向量 vs 混合检索的差异。

1. 进入知识库 → 检索测试台
2. 输入精确查询: "TK-20240001"
3. 观察: 纯向量结果分数低/不相关，混合结果（BM25）精确命中
4. 输入语义查询: "怎么把套餐换成更贵的"
5. 观察: 向量结果理解"换成更贵的=升级"，混合检索经 Rerank 后排名最优

**面试话术**: "纯向量召回对编号/专有名词盲目，BM25 补充了精确匹配能力。RRF 融合两路信号不依赖分数归一化——这个选择是故意的，因为向量相似度和 BM25 分数的分布差异大，RRF 只依赖排序位置更鲁棒。"

---

## 场景5: DeepAgent 报告生成（2分钟）

**目标**: 展示自主规划 vs 固定编排的对比。

1. 进入 DeepAgent → 报告生成
2. 选择预设 "生成本周工单积压分析报告"
3. 观察: 3步执行过程（查询统计→检索SOP→生成报告）
4. 查看最终报告（含数据概览+改进建议）

**面试话术**: "LangGraph 是固定编排——节点和边是提前定义好的。DeepAgent 是自主规划——接收自然语言目标，自己决定执行步骤。这里是3步固定骨架的简化版，但架构上预留了通用规划器的扩展空间。"

---

## 场景6: Trace 可视化（2分钟）

**目标**: 展示完整执行轨迹。

1. 进入后台 → 会话详情 → Agent 执行轨迹 Tab
2. 观察: 4步时间线（router蓝色→retrieval绿色→agent橙色→generation红色）
3. 每步展开可看详情（意图/置信度/检索分数/工具调用）

**面试话术**: "每条消息的执行轨迹都写入 MongoDB，包含意图识别、检索结果、工具调用、生成回答4个步骤。这是面试演示的重头戏——能清晰展示'多智能体+RAG+MCP'每一步做了什么，而不是黑盒。"
