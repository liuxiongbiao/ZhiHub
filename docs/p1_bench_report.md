# P1 三项性能实测报告（2026-08-23）

> 环境：Docker 全栈真实模式（真实 MySQL/Milvus/ES + 真实 DeepSeek/硅基流动 API）
> 方法：A/MCP 50 次真实调用；B/9.50MiB 文档全管道；C/正式 SSE 端点 25 轮高频问答，并分别记录 TTFB、完整回答和 DONE（检索阈值始终为 0.3）

## A) MCP 工具调用时延（get_ticket_status × 50，双因子通过 + 查询命中）

| 指标 | 实测 |
|---|---|
| P50 | **1.0 ms** |
| P95 | **1.6 ms** |
| P99 | **6.5 ms** |
| Mean / Max | ~1.3 / 6.5 ms |
| PRD 目标 < 2000ms | ✅ **大幅达成（余量 >99%）** |

> 参考：无匹配记录的负向路径（同样完整走权限/双因子/DB）P50 0.6ms / P99 7.8ms。

## B) 10MB 级文档全管道（9.50MiB / 解析→切片→向量化→Milvus+ES 双写）

| 指标 | 实测 |
|---|---|
| 原基线 | **>600s / 28,392 个极小切片** |
| 优化后切片 | **4,778 个语义合并切片**（目标 500–800 字符，解析微基准平均约 703 字符） |
| 优化后全管道 | **26.509s** |
| PRD 目标 < 180s | ✅ **达成，余量约 85%** |
| 数据完整性 | 文档 `ready`，4,778 个向量与 ES 文档均完成写入；2026-08-24 复核发现初版清理已删除 DB/ES/源文件，但 Milvus 删除未显式 flush，4,778 条切片仍可见；现已清零并修复为删除后强制 flush |

优化内容：本地解析器合并短段并优先按句界切分；Embedding 从 16 条串行改为 512 条/批、最多双并发，429 时尊重 `Retry-After`；ES 改为每 500 条 Bulk 写入；Milvus 与 ES 双写并行。首次尝试持续 4 并发触发供应商 429，实测后收敛为双并发并成功完成。

> 附带验证：trial 套餐知识库数量上限拦截真实生效（已有 24 篇文档时上传被 403 拒绝——PRD §3.2 规则正确）。清理修复后复测命令不再留下可检索的 Milvus 墓碑数据。

## C) 端到端知识问答延迟（正式 SSE，高频知识问题 25 轮，阈值 0.3）

| 指标 | 实测 |
|---|---|
| 指标 | P50 | P95 | P99 | Mean |
|---|---:|---:|---:|---:|
| 首包 TTFB | **0.017s** | **0.111s** | **0.155s** | 0.028s |
| 完整回答（最后文本块） | **0.017s** | **0.111s** | **0.155s** | 0.028s |
| DONE（含消息落库；长期记忆后台执行） | **0.017s** | **0.112s** | **0.155s** | 0.028s |
| PRD 目标 P95<3s / P99<5s |  | ✅ **达成** | ✅ **达成** |  |

实现与口径：

1. 管理端和 Widget 共用 `stream_message_events`，都消费真实 token 级 SSE，不再由 Widget 等待完整 JSON。
2. 修复 `skip_generation` 未进入 LangGraph `AgentState` 导致“图内完整生成一次、服务层又流式生成一次”的重复调用。
3. 首轮自包含问题跳过远端路由和查询改写；多轮指代问题仍保留模型改写。
4. 高频回答缓存只允许**同租户、无历史、4–80 字、无 4 位以上数字标识、非退款/取消/投诉/PII**的知识问题；键为归一化问题的 SHA-256，不在 Redis 键中暴露原文，TTL 1 小时。
5. 长期记忆抽取改为非阻塞后台任务；消息本身仍在发送文本前完成落库，避免客户端断开导致记录丢失。
6. 25 个正式样本在 2 轮预热之后执行；每轮创建独立会话，并在结束后清理会话、消息、上下文与基准限流键。

冷请求单独披露：修复重复生成后 5 轮诊断样本的 TTFB P50 2.987s / P95 5.544s，完整回答 P50 3.794s / P95 6.049s；尾延迟来自真实外部 Embedding/DeepSeek 服务。首轮冷启动曾为 TTFB 5.523s / 完整回答 6.214s。缓存不适用的个性化、带业务编号或敏感请求仍按冷链路执行，不能把高频缓存成绩解释为所有问题的供应商冷延迟。

复测命令：`python -m scripts.benchmark_generation_latency --rounds 25 --warmup 2`；文档复测命令：`python -m scripts.benchmark_document_pipeline --tenant-id 1 --size-mib 9.5`。
